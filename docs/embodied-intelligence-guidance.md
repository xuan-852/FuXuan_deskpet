# 符玄具身智能指导文档

> **定位**：本文件是符玄桌宠具身智能的产品与工程指导规范。它约束后续的身体能力标定、动作控制、LLM 行为接口、云端视觉认证与验收；未被认证的能力不得被宣传或开放给 LLM。
>
> **适用范围**：`Live2DFramework`、`ActionAgent`、动作工具、鼠标互动、桌面移动、动作验证与能力清册。
>
> **非目标**：不实现语音识别；不将桌宠描述为真实机械臂或物理机器人；不读取屏幕内容、活动窗口标题或剪贴板以制造“感知”；运行时不依赖云端视觉模型。

---

## 一、最终目标

符玄不是“LLM 播放动作列表”，而是一个拥有持续身体状态的桌面角色：她能依据已授权、用户可感知的互动形成行为意图；在当前 Live2D 模型真实可表达的边界内，自然地看、动、停、收束和回应；动作可解释、可打断、可恢复。

验收表述：

> 符玄能够基于鼠标互动、对话状态与自身身体状态，提出并执行可解释的身体意图；所有动作都由已认证能力组成，能连续过渡、自动降级、被安全打断并恢复。

## 二、不可违反的原则

1. **身体先于心智**：先获得真实、可控、可验证的身体能力，再接入情绪、人格和复杂自主行为。
2. **语义骨架先于原始参数**：LLM 不直接提交 `Param*` 值；它面对的是骨架节点、认证原语和技能。
3. **事实先于命名**：`fuxuan_map.json` 只是候选映射。运行时读回、视觉变化、复位与重复性证据才决定参数是否可用。
4. **连续姿势先于动作片段**：中性姿势是安全锚点，不是每个动作的强制终点；动作应保留自然余韵并从当前姿势过渡。
5. **本地安全先于云端智能**：实时控制、仲裁、限位、取消、恢复均在本地完成；云端仅用于离线/批量视觉认证。
6. **可见交互先于隐式监控**：第一阶段注意力只使用鼠标位置、停留、点击、拖拽和桌宠直接互动。
7. **优雅降级先于假装完成**：不可表达的请求应转为已认证的近似表达；没有安全替代才拒绝。

## 三、身体抽象

Live2D 是参数驱动的网格形变，不是天然的三维骨骼。因此系统建立的是**虚拟人体骨架与运动依赖图**：经标定后，把真实参数挂接到语义节点，绝不假设静态参数名必然正确。

```text
Root（桌面位置、移动、停靠）
└── Torso（躯干、重心）
    ├── Shoulder-L / Shoulder-R
    │   └── UpperArm → Forearm → Hand → Fingers
    ├── Head
    │   ├── Eyes / Brows / Mouth / Face
    │   └── Hair / Accessories
    └── Skirt / Clothing
```

| 类别 | 例子 | 规则 |
|---|---|---|
| 主骨架 | Root、躯干、头、肩、手臂、手 | 认证后可作为动作规划的主目标。 |
| 从属身体 | 手指、眼睛、眉毛、嘴部 | 由主节点驱动或作为受限叠加层。 |
| 物理附属 | 发丝、裙摆、衣物 | 默认随主骨架的方向、速度、幅度跟随；不由 LLM 逐帧控制。 |
| 表情覆盖 | 眼神、眉形、口型 | 可与部分骨架动作并行，必须遵从冲突矩阵。 |
| 非身体效果 | 法阵、粒子、镜头 | 仅是表达效果，不进入人体骨架或人体动作语义。 |

## 四、身体状态与动作生命周期

### 4.1 `PoseState`

系统必须维护持久姿势状态，至少涵盖 Root、躯干、头眼、双臂/手、基础表情、附属模块状态和当前资源占用。普通动作结束后应收束到自然姿势，而非统一清零。

### 4.2 生命周期

```text
Requested → Validating → Queued → Preparing → Executing → Settling → Completed
                                      │              │
                                      ▼              ▼
                                 Rejected     Cancelled / TimedOut
                                                    │
                                                    ▼
                                             SafeRecovery
```

- `SafeRecovery` 是所有异常、取消、退出、渲染器重建的必经路径：释放资源、恢复动作写入值、恢复符合条件的移动状态。
- `stop_action`、退出、系统恢复和渲染器失效立即抢占。
- 普通用户动作最多允许当前动作自然收束 1 秒，之后必须抢占。
- 同一资源同一时刻只允许一个所有者；所有锁带 `requestId`、所有者和过期时间。

### 4.3 资源与并行

资源至少为：`Locomotion`、`Torso`、`Head`、`Face`、`LeftArm`、`RightArm`、`Hands`、`SecondaryMotion`、`Effects`。

- 走路与全身姿势默认互斥。
- 面部、注视可在认证白名单内与走路并行。
- 头发、裙摆等附属物不抢占主骨架资源。
- 未经认证的并行组合一律视为冲突。

## 五、行为与交互

### 5.1 三层自主性

```text
反射层：鼠标停留/点击/拖拽/边界 → 本地即时反应
行为层：姿势整理、呼吸、轻微空闲、注意力衰减 → 本地规则
意图层：低频 LLM 提案 → Coordinator 审核后执行
```

LLM 只能提出意图，不拥有执行权。例如：

```json
{
  "purpose": "acknowledge_user_attention",
  "candidate_skill": "gentle_gaze_and_nod",
  "style": "subtle",
  "attention_target": "cursor",
  "urgency": 0.35
}
```

Coordinator 必须核验能力认证、当前姿势过渡、资源冲突、冷却、动作频率与安全条件。

### 5.2 注意力与隐私

`AttentionState` 仅保存目标类型、二维坐标、强度、置信度、过期时间和来源。它不写入长期鼠标轨迹或敏感应用内容。

- 快速掠过鼠标不触发动作；停留或明确点击才形成强注意力。
- 同类反应有冷却，默认只注视，不追逐鼠标。
- 第一阶段 Root 移动只响应明确鼠标线索、用户拖拽或点击引导，不自主漫游。
- 注意力过期后，姿势渐进收束。

### 5.3 上层行为风格

必须预留 `Quiet`、`Balanced`、`Expressive` 三种可配置行为画像及其占比接口。首轮测试采用**平衡偏活跃**画像，以充分暴露幅度、组合、抢占、恢复和视觉可见性问题。生产默认值由用户偏好决定。

## 六、能力认证普查

第一版不是预设少数动作，而是完成当前模型的身体能力发现。输出必须包含：参数事实表、视觉影响图、骨架挂接图、冲突矩阵、版本化能力清册。

### 6.1 分阶段流程

1. **全量本地探测**：对语义地图与运行时真实参数进行存在性、写入/读回、负中正多档幅度、视觉差异、复位、重复性测试。
2. **局部组合探测**：验证头+眼、躯干+手臂、手臂+手、走路+上半身、表情+姿势、主骨架+附属模块等组合。
3. **云端语义认证**：对有稳定本地证据的主骨架候选和高价值组合生成标准化拼图，判断身体部位、方向与动作语义。
4. **稳定性压力验证**：连续动作、抢占、取消、走路交接、窗口重建、长时间运行后检查锁、姿势、形变和恢复。

### 6.2 能力等级

| 等级 | 含义 | 可否常规开放给 LLM |
|---|---|---|
| `Certified` | 可写、可见、方向稳定、可复位，且语义可信 | 可以 |
| `Supporting` | 可见但只适合作为主动作的辅助 | 仅由技能内部使用 |
| `Conditional` | 仅在指定基姿、资源或条件下安全 | 条件调用 |
| `Unreliable` | 易覆盖、方向不稳定、复位异常或形变风险 | 不可以 |
| `EffectOnly` | 非人体表达效果 | 仅受控表达层调用 |
| `Unsupported` | 不存在或无法表达 | 不可以，触发降级 |

## 七、云端视觉与证据治理

### 7.1 判定链

```text
本地运行时读回 + 图像量化
          ↓
DeepSeek Flash 主判
          ↓
GLM Flash 尽力旁证（单次、短超时、不阻塞）
          ↓
一致：认证；分歧：仲裁队列；仍不确定：产品负责人审核
```

- 云端只接收桌宠裁剪图、测试标识、参数摘要和结构化问题；不得上传桌面内容、聊天内容、窗口标题或密钥。
- 相同拼图、提示词、模型版本、参数摘要使用内容哈希缓存，禁止重复调用。
- 首轮 DeepSeek 消费上限为 27 元，预留 3 元保护余额；任务优先在低峰队列执行，支持断点续跑。
- GLM Flash 不可用只记为 `Unavailable`，不是参数失败。
- 正常样本只保留哈希、指标与结论；失败/争议截图最多保留 30 天。

## 八、LLM 控制协议

LLM 的输入是能力清册、当前 `PoseState`、注意力摘要、资源状态、冷却与近期行为摘要；它只能提出一个主要动作加一个伴随动作，总时长默认不超过 4 秒。执行后必须基于实际结果重新规划，不能假设动作已完成。

LLM 禁止：

- 直接输出原始 `Param*` 名和数值；
- 直接获取截图、调用视觉模型或扩大系统权限；
- 调用 `Unreliable`、`EffectOnly`、`Unsupported` 能力作为人体动作；
- 在未通过 Coordinator 的情况下抢占、移动或持续控制身体。

## 九、正式实施顺序与门槛

1. 建立可复现的标定环境、运行时参数清单与全量本地探测器。
2. 建立标准化拼图、双模型任务队列、缓存、预算账本和仲裁报告。
3. 生成第一版能力清册与骨架挂接图；只从 `Certified` 能力构建原语。
4. 建立 `PoseState`、Coordinator、资源仲裁、取消和 `SafeRecovery`，并接入已有动作入口。
5. 迁移预设、表情、参数控制、空闲调度和自主动作到统一入口。
6. 接入 LLM 意图协议与鼠标注意力；最后才扩展文字对话身体联动与情绪系统。

每一步均须在 `FU_XUAN_DATA` 隔离数据目录和 `.test_mode` 下测试。云端调用、生产记忆污染、未认证参数、绕过 Coordinator 的持续参数写入均为阻断发布的问题。

## 十、验收标准

第一版通过不以“动作数量”计，而满足以下事实门槛：

1. 全量参数有运行时探测结果，不存在“仅因映射表命名就默认可用”的参数。
2. 主骨架与高价值组合动作有本地证据和云端语义判定；未完成云端认证者明确标为待评估，而非默认为通过。
3. LLM 常规可调用能力全部为 `Certified`，每项有版本、证据、资源要求、前置条件、后置姿势和降级策略。
4. 走路交接、动作并行、取消、退出、渲染重建和长时运行均不会遗留锁、姿势或异常形变。
5. 普通用户能够通过可见鼠标互动理解她为何看、动、停；系统不因隐式屏幕监控获取生命感。
