## 3. 初始问题清单

优先级：P1 为隐私、数据或核心交付阻塞；P2 为可靠性与验证可信度缺口；P3 为维护问题。编号 E* 是本报告编号，与旧文档的问题编号分开。

### E01 · P1 · Ollama 下载脚本在 PowerShell 5.1 下解析失败【已复现】

- 位置：`installer/components/download-ollama.ps1:1`；调用方 `installer/components/install-ollama.cmd:40`。
- 文件前三字节是 `112,97,114`（`par`），没有 UTF-8 BOM。脚本含中文，调用方使用 `powershell -File`。
- 本机 `Parser.ParseFile` 产生 8 个解析错误；用 UTF-8 明确解码后 `Parser.ParseInput` 为 0 错误，定位为文件编码与 PS 5.1 默认解码不兼容。
- 影响：需要下载 Ollama 的安装路径在进入下载逻辑前失败；不是网络问题。本轮未运行下载器或安装器。
- 修复与验收：按 `.editorconfig` 为该 PS1 使用 UTF-8 BOM；原生 PS 5.1 解析零错误，再在缺少 Ollama 的隔离机器验证完整安装路径。

### E02 · P1 · EditMode 测试直接读取真实剪贴板【静态确认】

- 位置：`Assets/Editor/Tests/ToolEngineTests.cs:185`、`:225`、`:250`（相对 Unity 工程）。
- 所谓只读白名单包含 `get_clipboard`，专门测试也直接执行它；另一个测试遍历所有异步工具并传 `{}`。
- `ToolRegistry.Execute`（`Assets/Scripts/ToolEngine/ToolRegistry.cs:119`）直接调用工具；`ClipboardFileTools.cs:22` 直接调用系统剪贴板读取，无测试模式拦截。
- 生产聊天和提醒上层有危险操作确认，不能推断生产聊天也绕过审批；问题是测试绕过了上层。
- 截图工具当前有禁云端前置拦截，因此不声称本轮截屏或外发已发生。测试清单仍不应依赖各工具内部的偶然保护。
- 修复与验收：剪贴板使用替身；移除空参遍历异步工具，按只读白名单和受控夹具分组。自动测试在无确认情况下不得读取剪贴板、截屏或产生系统副作用。本轮未执行这些测试。

### E03 · P1 · 构建与冒烟会强杀生产实例，隔离目录删除缺少边界校验【静态确认】

- 位置：`build.ps1:194`；`scripts/test/runtime_smoke.cjs:67`、`:145`、`:149`、`:233`。
- 构建在区分 Quick/完整构建前按名称强制终止 DesktopPet；冒烟使用 `taskkill /IM DesktopPet.exe /F /T`，不是只清理自己启动的 PID。
- 本次检查时确有 DesktopPet 进程运行。直接执行这些入口会中断现有实例，强杀可能跳过正常保存。
- 冒烟对 `FU_XUAN_TEST_DATA` 指定路径直接递归删除，没有验证其与生产根不同、是否为专属临时子目录。配置错误时存在删除生产数据的路径，本轮未触发。
- `--keep-alive` 也仍会删除 `.test_mode` 并尝试删除测试目录，不能认为留下的是持续受保护的测试实例。
- 修复与验收：仅清理测试自身 PID；测试目录创建时校验规范化路径和专属标记，拒绝生产目录、父目录和重解析点；保留进程时保留隔离目录与测试标记。验证生产与测试实例并存且生产不受影响。

### E04 · P2 · “生产记忆零污染”断言会漏报【静态确认】

- 位置：`scripts/test/runtime_smoke.cjs:34`、`:239`。
- 未配置环境变量时固定检查 `D:\DesktopPetData`，与 `DataPathConfig.cs:49` 的旧 C 盘目录优先、用户 LocalAppData 默认规则不同。
- 断言只检查“原来存在、现在仍存在、mtime 变化”。原来不存在而被新建、原来存在而被删除，都不进入失败列表。
- 影响：即使脚本打印零污染，也不能证明实际生产根全部未变化。
- 修复与验收：统一解析生产根，比较存在性与文件内容哈希，并明确受保护文件范围；用临时夹具验证新增、删除、修改均被检测。不得在真实记忆上做破坏测试。

### E05 · P2 · 桥接同步子进程阻塞整个 HTTP 事件循环【静态风险】

- 位置：`openclaw_bridge.js:675`（办公 60 秒超时）、`:1770`（PDF 提取 120 秒超时）；LaTeX 编译也使用同步调用。
- 慢生成期间 Node 主线程阻塞，健康检查、任务轮询/取消和 WebSocket 消息处理都可能延后。任务并发数量上限不能消除这种阻塞。
- 本轮未对生产桥接进行阻塞压测，不声称已测得具体延迟。
- 修复与验收：异步子进程、并发限制和超时清理；在独立桥接进程中使用受控慢任务，同时测健康响应与取消时延。

### E06 · P2 · 核心记忆直接覆盖写入，缺少原子替换【静态风险】

- 位置：`PetMemory.cs:638`、`KnowledgeBaseManager.cs:738`。
- 使用 `File.WriteAllText` 覆盖正式 JSON；该保存路径未见临时文件加原子替换。写入过程中崩溃或断电可能损坏文件。
- 这是数据可靠性风险，本轮没有破坏真实数据或复现数据丢失；手工备份工具不等于每次写入具备事务性。
- 修复与验收：临时写入、校验后替换、最近有效备份和损坏恢复；使用隔离夹具验证写入中断后旧数据仍可加载。

### E07 · P2/P3 · 测试与文档的“通过”含义不够一致【已核对】

- 冒烟 `runtime_smoke.cjs:216` 仅把 NRE 判失败，其他 Exception 只告警；不支持据此宣称“零异常”。命令留痕也不足以证明画面和操作后状态正确。
- `docs/modules/bridge-communication.md` 的健康端点表格写需 token，同节说明写免鉴权；本次实测为免鉴权。
- `docs/build-workflow.md` 最新记录写 160/159/0/1，本机历史 XML 是 161/160/0/1；两者不是本轮测试结果。
- `AGENTS.md` 与架构文档写 Scripts 122 文件，当前该目录是 123 文件。
- 盘点范围内 128 个 CS/PS1/CMD 文件不满足文档要求的 BOM；并非全都会运行失败，实际 PS1 故障见 E01。
