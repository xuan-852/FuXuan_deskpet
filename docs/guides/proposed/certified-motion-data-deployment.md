# 认证动作曲线数据的生产部署与真人验收（提案）

> **状态**：提案（`proposed`），未经批准不得实施。
>
> **上位决策**：[产品方向基线](../decisions/2026-09-15-product-direction-baseline.md) §4、[L3 认证指导](approved/l3-embodied-skill-certification.md)、[外部动作素材导入](../../truth/l3-external-motion-import.md)。

## 1. 问题

认证动作的曲线数据（`certified_motions/<skillId>.json`）因许可约束不入版本库，仅由隔离测试脚本在临时数据根中手工放置。**当前生产数据根没有这些文件**：真实用户即使通过对话成功路由到 `request_body_skill`，执行器也会在加载曲线时失败。认证流水线端到端断在数据部署这一步；且所有自然度分数均来自双模型评审，尚无真人目视签字。

## 2. 目标

- **FR-01**：定义曲线数据到达运行环境的合规途径，使已认证技能在真实使用中可完整执行。
- **FR-02**：建立首个真人端到端验收：真实对话触发 `request_body_skill` → 动作在真实窗口播放 → 人工目视自然度签字，记录进 `docs/truth/`。

非目标：不改认证结论、不新增技能、不开放主动/自主行为、不解决安装包分发（另立发布任务）。

## 3. 合规途径（按 Live2D Free Material License v1.6）

| 场景 | 方式 |
|---|---|
| 本机开发/验收 | 曲线派生自已本地留存的官方素材（`assets/external_motions/`，gitignore），拷贝到本机生产数据根属个人使用，不构成再分发 |
| 未来产品分发 | 以「作品内嵌」携带派生曲线数据并在关于页/安装包附版权声明（素材仓库、许可链接、许可版本）；禁止让用户单独取得素材数据文件 |

## 4. 验收步骤（真人签字门槛）

1. 将 6 个已认证技能的曲线 JSON 部署到生产数据根 `certified_motions/`（仅新增文件）。
2. 正常启动桌宠（生产数据、无 `.test_mode`），在真实聊天中用自然语言请求身体动作（如"摇摇头""眨眨眼"）。
3. 核对：LLM 路由到 `body` 意图并调用 `request_body_skill`；动作完整播放、自然收束；日志出现 `certified-motion-completed` 且无异常恢复。
4. 对每个可触发技能给出目视结论（自然/可接受/不自然），记录到新的 truth 文档并同步模块文档。

## 5. 实施授权边界

- 允许：数据根新增曲线文件、真人验收取证、truth/模块文档、安装包分发方案（后续独立指导）。
- 禁止：把素材原始文件或曲线数据提交进版本库、跳过版权声明对外分发、以验收名义开放主动行为或未认证技能。
- 阻断：许可条款变化、真人验收结论与认证分数显著相悖（须回查认证链路，`BlockedByDecision`）。
