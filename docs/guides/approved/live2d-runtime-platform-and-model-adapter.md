# Live2D 运行时平台与模型适配器

> **状态**：已批准的平台指导文档（2026-09-18）。
> **上位决策**：[Live2D 平台与符玄私有 Fixture 范围决策](../../decisions/2026-09-18-live2d-platform-and-fuxuan-fixture-scope.md)。
> **关联规范**：[文档治理与任务分发规范](../../decisions/documentation-governance.md)、[通用 Live2D 参数能力探测器](generic-live2d-capability-probe.md)、[统一生命控制环](unified-life-control-loop.md)。

## 1. 目标与非目标

本指导定义桌宠运行时平台如何消费具有合法使用权的 Live2D 模型，以及如何把模型专属参数包装为受证据约束的语义能力。

目标：

- **FR-ADAPTER-01**：分离平台代码、模型资源、模型适配器和角色权利；
- 通过隔离 Probe 发现机械、视觉、时序和关系证据；
- 以单写入者、租约、停止、恢复和降级保证运行时安全；
- 让用户可以为自有模型建立本地适配记录，而不要求平台仓库分发该模型。

非目标：

- 当前不提供任意 Live2D 模型热插拔或运行时换模；
- 不把现有固定 Fuxuan 资源宣传为通用模型加载器；
- 不从运行时导出物反推 PSD、网格、变形器、原始动作工程或权利；
- 不把缺少证据的参数、动作或语义直接交给 LLM；
- 不替用户判断角色 IP、第三方模型或外部素材的发布/商业许可。

## 2. 分层与公开接口

| 层 | 内容 | 当前状态 |
|---|---|---|
| 平台运行时 | ChatManager、ToolEngine、动作仲裁、状态恢复、渲染窗口、测试和数据隔离 | 当前项目已有实现，按代码真相维护 |
| 模型资源 | `.model3.json`、`.moc3`、纹理、物理、部件描述和 Prefab | 由用户或权利人提供，不由平台许可自动覆盖 |
| 模型适配器 | 参数发现、范围、读写复位、证据哈希、语义候选和降级 | 接口目标已定义；当前生产路径仍是固定 Fuxuan 适配案例 |
| 能力目录 | 只读候选清单，包含证据、分类和 `mapWriteAllowed=false` | Probe 证据输出，不等于认证 |
| 认证映射 | 人工复核后批准的模型专属语义映射 | 当前仅允许已有生产事实；fixture 不得写入 |

适配器至少需要能够报告模型/资源哈希、发现参数与范围、执行隔离写入/读回/复位、冻结干扰写入者、采集统一帧并返回证据。适配器不拥有公开模型资源的许可，也不能绕过任务包路径边界。

## 3. 当前代码真相

当前 `Live2DRenderer` 不是通用模型 provider：编辑器优先加载 `Assets/Live2D/Models/Fuxuan/符玄.prefab`，随后使用 `Resources.Load` 回退；运行时再固定读取 `StreamingAssets/Live2D/Fuxuan/符玄.model3.json`。这三层路径属于现有本地案例，不能被写成用户可任意选择的模型目录。

当前 Ollama 模型名是另一条链路：它表示本机已安装的 model tag，不是 Live2D 角色模型资源，也不支持任意权重文件路径导入。Live2D 换模和本地 LLM provider 插件均不是本指导已实现的能力。

## 4. 探测、认证与降级

1. 输入模型必须位于隔离目录，并有来源、许可和哈希记录。
2. Probe 只读或写入隔离副本，输出可复核证据；不得修改正式映射、生产动作或 LLM schema。
3. 每项能力至少需要机械、视觉、时序和关系证据；缺一项保持 `Candidate`、`Supporting` 或 `Conditional`。
4. 只有人工复核、回归、复位和并发边界均通过，才能进入模型专属认证映射。
5. 模型缺失、资源损坏、参数不支持、动作超时或停止恢复失败时，运行时必须降级为安全姿态/无动作，并保留可诊断状态。

`FixtureOnly`、`CaseStudy`、`ReviewFailed` 和 `BlockedByEvidence` 不得映射成 `Approved`、`Certified` 或 `ProductionReady`。

## 5. 运行时安全边界

- Live2D 参数写入遵守单写入者和动作租约；停止操作必须可抢占并恢复基线。
- 模型适配器不得绕过 `ParameterCommitBridge`、输入协调、生产数据隔离或危险工具审批。
- 测试必须设置隔离 `FU_XUAN_DATA`（或未来 adapter 的独立数据根）并创建 `.test_mode`；不得污染生产记忆。
- 云端视觉只消费明确授权的隔离帧；平台不因能力探测自动上传模型内容。
- 安装包和公开 Release 不得自动包含未经权利复核的第三方模型、纹理、动作、专属参数配置、Cubism 工程或组合资源。

## 6. 验收矩阵

| ID | 证据 | 通过标准 |
|---|---|---|
| **AC-FIXTURE-01** | fixture 根状态说明、来源/许可登记、哈希与失败验收报告 | 状态保持 `FixtureOnly / CaseStudy / ReviewFailed / BlockedByEvidence`；自动结构检查不得覆盖视觉失败结论 |
| **AC-FIXTURE-02** | Git 路径审计、任务包禁止路径和文档索引 | 不产生 `.cmo3`、运行时导出、Unity production candidate、正式映射、生产动作、LLM 暴露或安装包资产 |
| **AC-ADAPTER-01** | Probe 机械/视觉/时序/关系证据及模型资源哈希 | 候选能力不直接写正式映射，缺证据项不升级为 `Certified` |
| **AC-ADAPTER-02** | 隔离运行日志、停止/取消/超时/损坏资源用例 | 使用独立数据根和 `.test_mode`；失败后恢复安全姿态且不污染生产数据 |

## 7. 实施授权边界

平台任务可以修改通用运行时、适配器契约、Probe、隔离测试和验证后文档，但必须声明允许/禁止路径、证据产物和失败恢复。模型资源任务只能修改用户有权处理的本地目录；不得写入生产模型目录、正式映射、生产动作、LLM 技能、installer、Build 或生成索引。

任何从私有 fixture 转向生产的任务必须新建决策、批准指南和任务包，并重新完成权利复核、人工验收、隔离导入、Probe 和回滚设计。
