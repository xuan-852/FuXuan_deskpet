>
> **上位决策**：[产品方向基线 §2](../../decisions/2026-09-15-product-direction-baseline.md#2-l1启动退出数据与降级)、[文档治理规范](../../decisions/documentation-governance.md)。

> **现有代码真相入口**：[运行时状态模块](../../modules/runtime-readiness.md)、[已知 Bug 与验收点](../../project-bugs-and-acceptance.md)。两者不等同于本提案的完成状态。

## 1. 目标与非目标

**FR-L1-01**：桌宠在桥接、网络、云端、本地模型或密钥任一不可用时，仍能启动为可交互的本地桌宠：至少显示 Live2D、支持本地鼠标交互和设置入口。

**FR-L1-02**：所有可取消的请求具有可观测的终态；窗口关闭、测试结束、用户取消或预算耗尽后不得残留请求、锁或后台写入。

**FR-L1-03**：用户数据在异常退出、写入失败、损坏与版本升级时保持可恢复，自动化测试永不污染生产数据。

**FR-L1-04**：系统关机、正常退出、异常退出和不明中断分开记录，但都走安全清理路径；正常关机不能被误标为崩溃。

**FR-L1-05**：连续关键故障后提供安全模式，优先恢复可见模型、设置与恢复入口，而不是反复尝试高风险依赖。

非目标：本指导不重新设计桌面物理、动作控制、聊天人格或多屏体验；不允许为了健康检查而进行付费云端探测；不允许自动杀死/启动 PM2 或 Gateway。

## 2. 功能与公开接口契约

| 需求 | 契约 | 调用方可见结果 |
|---|---|---|
| FR-L1-01 | `RuntimeCapabilitySnapshot`：本地渲染、输入、存储、桥接、本地模型、云端分别给出 `Available/Unavailable/Degraded` 与无敏感信息原因 | UI 只显示真实可用能力，禁用项说明原因与恢复动作 |
| FR-L1-02 | `OperationHandle`：`requestId`、来源、开始/截止时间、取消能力、重试计划、成本类别与终态 | `Completed/Failed/Cancelled/TimedOut/BlockedByBudget` 之一 |
| FR-L1-03 | `PersistenceResult`：原子写入、备份/恢复来源、迁移版本和错误分类 | 写入失败不覆盖旧文件；恢复状态可记录 |
| FR-L1-04 | `ExitClassification`：`CleanExit`、`SystemShutdownLikely`、`AppCrashLikely`、`InterruptedUnknown` | 下次启动采用相应的恢复策略，不向用户伪报崩溃 |
| FR-L1-05 | `RecoveryMode`：`Normal/SafeRender/SafeMode`，含进入原因、禁用能力和显式退出条件 | 安全模式仍保留模型显示与设置，明确提示已降级 |

接口名称是目标契约，不代表当前代码已有同名类型。现有 `RuntimeReadinessService`、`ChatManager`、`DesktopPet.BeginShutdown` 等只能作为迁移候选，实施前必须建立对应代码真相。

## 3. 状态、数据与并发

```text
启动 → 本地基础检查 → Normal | SafeRender | SafeMode
任意运行态 → 退出意图/系统会话/异常证据 → ExitClassification → 幂等清理 → 下次恢复决策
任意 OperationHandle → Completed | Failed | Cancelled | TimedOut | BlockedByBudget
```

- **C-L1-01（本地优先）**：渲染、直接鼠标交互、设置与数据恢复不依赖桥接或模型健康。
- **C-L1-02（请求所有权）**：每个后台操作必须有单一拥有者和关联 ID；拥有者销毁时传播取消，不得遗留无主协程、线程或请求。
- **C-L1-03（退避）**：自动重试使用有限指数退避和熔断；用户显式重试可立即发起。依赖不可用期间不得无限刷日志/请求。
- **C-L1-04（数据安全）**：持久化使用临时文件+替换或等价原子策略；写前保留有限恢复副本；损坏文件隔离而非覆盖或删除。
- **C-L1-05（测试隔离）**：任何自动化运行必须以临时 `FU_XUAN_DATA` 和 `.test_mode` 启动，并对生产数据 mtime/哈希零变化断言。
- **C-L1-06（敏感信息）**：诊断、健康记录、异常原因和日志不得含 API Key、Token、完整对话、剪贴板、窗口标题或屏幕内容。
- **C-L1-07（安全模式）**：安全模式禁用云端、桥接、复杂动作与自动恢复循环；不得禁用 Live2D 可见性、设置或数据恢复入口。

## 4. 失败与恢复规则

| 情况 | 必须行为 | 禁止行为 |
|---|---|---|
| 桥接/网络/模型不可用 | 展示可理解原因；本地能力继续工作；有限退避 | 假装 AI 已回复、静默切云、反复拉起外部服务 |
| 云端预算或取消 | 请求进入明确终态并停止后续工具轮次 | 继续扣费、把取消视为成功 |
| 写入失败/损坏 | 保留原文件或恢复副本，隔离损坏件，提供恢复提示 | 覆盖、清空或自动删除用户数据 |
| 系统会话结束 | 以幂等清理为主，记录 `SystemShutdownLikely` 证据 | 因预通知提前破坏窗口/数据，或把关机一律记为崩溃 |
| 连续关键启动故障 | 进入安全模式并停止自动升级尝试 | 无限重启、隐藏故障、放弃模型显示 |

## 5. 可观测性与验收

| 验收 ID | 场景 | 证据 | 通过标准 |
|---|---|---|---|
| AC-L1-01 | 无桥接、无网络、无云端/本地模型 | 隔离播放器截图、状态日志、无外部请求断言 | Live2D 与本地设置可用；状态真实且可恢复 |
| AC-L1-02 | 用户取消、窗口关闭、预算拦截、超时 | 关联 ID 日志与自动测试 | 每个操作只有一个终态；无遗留请求/锁/后续扣费 |
| AC-L1-03 | 原子写故障、损坏 JSON、迁移失败 | 临时数据根故障注入和恢复断言 | 旧数据可保留/恢复；损坏件未被静默删除 |
| AC-L1-04 | 正常退出、系统会话消息、模拟崩溃/中断 | 隔离日志与下次启动状态 | 分类正确；清理幂等；正常关机不增加崩溃计数 |
| AC-L1-05 | 连续关键故障 | 隔离启动测试、截图、状态记录 | 进入安全模式，模型可见、设置可达、云端/桥接/复杂动作被禁用 |
| AC-L1-06 | 全部 L1 测试 | `build.ps1 -Quick`、EditMode、隔离 `runtime_smoke.cjs`、测试数据保护断言 | 构建和适用测试通过；生产数据零污染 |

## 6. 尚待人工确认，未确认前不得批准

1. **D-L1-01**：何种“关键故障”计入安全模式，以及连续次数和观察窗口。
2. **D-L1-02**：普通健康记录的精确保留天数与最大字节数。
3. **D-L1-03**：迁移副本数量、保留期和用户可见恢复流程。
4. **D-L1-04**：`InterruptedUnknown` 对用户的具体提示文案与是否提供一键诊断导出。

## 7. 实施授权边界

- **未来允许范围**：运行时就绪、数据路径/持久化、请求生命周期、退出/安全模式、隔离测试与其直接文档。
- **禁止范围**：未经独立指导文档修改动作仲裁、角色人格、窗口物理、联网检索、工具权限或安装器行为。
- **阻断条件**：任何需要收集新用户数据、访问窗口标题/屏幕内容、自动启停外部服务、改变云端成本策略或迁移/删除用户数据的实现，必须 `BlockedByDecision`。
