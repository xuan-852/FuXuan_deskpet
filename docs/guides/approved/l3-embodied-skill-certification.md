# L3 具身技能认证与动作协调指导文档

> **状态**：已批准；只允许按受限任务包建立候选证据，禁止向 LLM 开放未认证能力。
>
> **上位决策**：[产品方向基线 §4](../../decisions/2026-09-15-product-direction-baseline.md#4-l3具身动作与-live2d-能力认证)、[具身智能指导](../../embodied-intelligence-guidance.md)、[具身 AI 优化架构](../../embodied-ai-optimization-architecture.md)。
>
> **现有代码真相入口**：[动作系统模块](../../modules/action-agent.md)、[Live2D 渲染模块](../../modules/live2d-rendering.md)。历史 `fuxuan_map.json`、MotionMemory、旧视觉评分和报告仅是候选证据。

## 1. 目标与非目标

**FR-L3-01**：建立基于真实模型表现的虚拟人体骨架、参数依赖图和能力清册；任何参数映射须由当前模型的证据证明。

**FR-L3-02**：所有动作来源统一进入一个协调器，按资源、优先级、生命周期、取消和恢复仲裁。

**FR-L3-03**：只把通过机械、视觉、语义和时序自然度认证的技能开放给运行时；LLM 只选择语义技能，不直接写 `Param*` 或裸关键帧。

**FR-L3-04**：离线双模型视觉评估有成本上限、证据缓存和人工升级路径，不成为运行时依赖。

非目标：不把 Live2D 描述为真实骨骼/机器人；不实时把屏幕内容送云端；不因旧高分记录自动放行技能；不让自然语言生成动作直接进入用户运行时。

## 2. 目标组件与接口

| 组件/接口 | 输入 | 输出/职责 |
|---|---|---|
| `CapabilityCensus` | 参数候选、当前模型版本、标定计划 | 机械/视觉证据及 `Certified/Supporting/Conditional/Unreliable/EffectOnly/Unsupported` 分类 |
| `VirtualSkeleton` | 已认证节点与依赖 | Root、躯干、头脸、肩臂手及衣发附属关系 |
| `ActionRequest` | 来源、语义目标、技能 ID、优先级、超时 | 唯一动作准入请求；无原始参数接口 |
| `EmbodiedCoordinator` | 请求、姿态、资源占用、环境状态 | 排队/执行/降级/拒绝/取消和结果 |
| `CertifiedSkillRegistry` | 技能定义、版本、认证证据 | 运行时唯一可调用技能集合 |
| `CandidateEvidence` | 本地轨迹、截图、双模型评估、人工结论 | 候选技能审计与复测依据 |

## 3. 硬约束与生命周期

```text
Candidate → Mechanical → Visual → Semantic → Naturalness → CertifiedSkillRegistry
      └──────────────────────────────→ Rejected / LegacyCandidate

ActionRequest → Validating → Queued → Preparing → Executing → Settling → Completed
                                      ↘ Rejected / Cancelled / TimedOut → SafeRecovery
```

- **C-L3-01**：渲染器只能执行协调器已授权的写入；`play_action`、`control_body`、动作生成、空闲、鼠标与地面行为均通过 `ActionRequest`。
- **C-L3-02**：资源至少区分移动、主姿势/躯干、头脸、左右臂手、次级效果。运行时最多并行：1 移动 + 1 主姿势/肢体 + 1 注视/脸部 + 1 次级层；更多组合必须离线认证。
- **C-L3-03**：每个技能声明模型/映射/渲染版本、前置姿态、占用资源、进入/执行/收束/取消、超时、成功指标和降级技能。版本变化使关联认证失效。
- **C-L3-04**：自然度是硬门槛；视觉可见或语义正确不足以允许自主调用。自然度失败仅可为 `Supporting/Unreliable`。
- **C-L3-05**：经验权重只在已认证技能中排序冷却、选择与复测优先级，绝不改变认证安全结论。
- **C-L3-06**：LLM 只获得 `Completed/Downgraded/Interrupted/Rejected/TimedOut` 与简短语义结果，绝不回传原始参数轨迹。
- **C-L3-07**：`SafeRecovery` 释放资源，收束到自然安全姿势并按条件恢复 L2 行为；取消、退出、渲染器重建均必须经过它。

## 4. 认证与云端成本

1. 本地扫描当前模型的写入、读回、范围、复位、重复性与组合冲突。
2. 采集固定视角、固定时长的时序截图/拼图，先以本地指标排除不可见、抖动和资源冲突。
3. 离线 DeepSeek 为主评，GLM Flash 为独立、非阻塞副评；分歧由主代理复核，仍不确定才交人工。
4. DeepSeek 总预算最多 27 元，保留 3 元；仅离峰批量执行，缓存请求/响应/截图哈希；失败和争议证据保留 30 天。
5. 候选自然语言动作、旧 MotionMemory 和历史高分均先进入 `LegacyCandidate`，重跑当前认证后才可入库。

## 5. 验收

| 验收 ID | 证据 | 通过标准 |
|---|---|---|
| AC-L3-01 | 当前模型参数普查与复位日志 | 每项能力都有分类、版本与证据，不把候选当认证 |
| AC-L3-02 | 多来源动作请求集成测试 | 无来源绕过协调器或直接竞争参数 |
| AC-L3-03 | 资源冲突/取消/超时/渲染重建测试 | 单一所有者、终态明确、必经安全收束 |
| AC-L3-04 | 时序截图、局部指标、双模型评估 | 自然度达标才入注册表；分歧有升级记录 |
| AC-L3-05 | 隔离数据根、预算与缓存日志 | 测试零污染；不超预算；运行时零云端视觉调用 |
| AC-L3-06 | Quick、EditMode、隔离运行时测试 | 构建和适用测试通过，生产数据未改变 |

## 6. 尚待人工确认

1. **D-L3-01**：自然度评分量表、最低分及“现有硬编码步行基线不可退化”的量化门槛。
2. **D-L3-02**：首轮普查的优先骨架部位与每批云端预算分配。
3. **D-L3-03**：何类视觉分歧可由主代理裁决，何类必须提交人工。

## 7. 实施授权边界

- **未来允许范围**：动作协调、能力普查、认证账本、动作测试、离线视觉证据与直接文档。
- **禁止范围**：运行时云端视觉、原始参数 LLM 控制、扩大用户监控、把未认证候选加入主动行为。
- **阻断条件**：模型/映射/渲染顺序变更、预算上限调整、采集新用户数据、认证结论与产品方向冲突，必须 `BlockedByDecision`。
