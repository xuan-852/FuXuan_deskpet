# 统一生命控制闭环指导文档

> **状态**：已批准（2026-09-18）；由产品负责人授权启动。本文定义跨 L1--L5 的集成迁移，不把目标接口描述为既有实现。
>
> **上位决策**：[产品方向基线](../../decisions/2026-09-15-product-direction-baseline.md)、[文档治理规范](../../decisions/documentation-governance.md)、[L3 具身技能认证](l3-embodied-skill-certification.md)、[L5 记忆、人格与主动互动](l5-memory-personality-proactive.md)。
>
> **代码真相入口**：[动作系统](../../modules/action-agent.md)、[运行时状态](../../modules/runtime-readiness.md)、[记忆人格](../../modules/memory-personality.md)。

## 1. 目标与非目标

**FR-ULC-01**：建立唯一的本地控制闭环：明确交互或内部反射生成语义请求，经仲裁和已认证执行器完成后，写入无敏感事件、结果和下一次策略依据。

**FR-ULC-02**：所有生产身体写入者均须有可查询的所有者、资源声明、生命周期和恢复路径；迁移期间旧写入者先成为受控适配器，禁止静默改变视觉表现。

**FR-ULC-03**：建立短期事件、注意力、身体状态和具身经验之间的最小因果链；记忆和情绪只能消费最小化事件摘要，不得记录窗口标题、剪贴板、屏幕内容或完整对话。

**FR-ULC-04**：每一次自动或用户触发的动作都可解释为“谁发起、为何接受/拒绝/中断、是否恢复、对下次选择有何影响”。

非目标：不新增未经认证的动作；不让 LLM 写原始参数；不接入云端视觉运行时；不模拟真实生物、真实骨骼或未获授权的桌面监控；不因本迁移改造模型资产或 3D 渲染。

## 2. 目标闭环与公开契约

```text
显式交互 / 本地反射
  -> PerceptionEvent (最小化、可过期)
  -> AttentionState + EnvironmentState
  -> IntentRequest / ActionRequest
  -> EmbodiedCoordinator + BodyStateStore
  -> 已认证技能或受控旧适配器
  -> ExecutionResult + EmbodiedEvent
  -> ExperienceRecord
  -> 情绪、记忆与下一次策略（均为受限消费者）
```

| 契约 | 最小字段/职责 |
|---|---|
| `PerceptionEvent` | UTC、来源、种类、关联 ID、无内容摘要、过期时间；只接收桌宠直接交互和已授权的本地模式事件。 |
| `BodyStateSnapshot` | 版本、姿态语义、当前动作/表达/视线/移动、资源锁、写入者、恢复和渲染健康；物理位置/速度与视觉姿态分层记录。 |
| `ActionRequest` | 来源、关联 ID、语义技能、优先级、资源、超时；绝无裸 `Param*`。 |
| `EmbodiedEvent` | 请求、状态迁移、原因、资源、时长、状态版本和参数摘要哈希；仅追加、无敏感内容。 |
| `ExperienceRecord` | 技能版本、前后状态版本、结果、是否中断/恢复、用户可见反馈、下次策略；不保存截图或桌面内容。 |

## 3. 硬约束

- **C-ULC-01**：Unity 主线程为 Live2D 参数唯一提交线程；任一执行器都必须通过协调器登记所有者与资源。
- **C-ULC-02**：退出、取消、超时、渲染失效和抢占必经幂等 `SafeRecovery`；不得遗留移动锁、输入租约或参数覆盖。
- **C-ULC-03**：认证安全与经验评分隔离；经验只排序已认证技能，不能把候选提升为可调用能力。
- **C-ULC-04**：注意力第一版仅来自鼠标停留/点击/拖拽、桌宠直接交互和用户配置的模式事件。历史窗口标题、浏览器标签、剪贴板路径默认关闭并从闭环消费者移除。
- **C-ULC-05**：自动动作、本地反射和测试绝不触发云端调用；视觉评测仅为隔离、显式授权的离线流程。
- **C-ULC-06**：所有测试使用临时 `FU_XUAN_DATA` 与 `.test_mode`，不得污染生产记忆、人格、活动或动作经验。

## 4. 分阶段实施与验收

### Phase A — 控制面与迁移清册（P0）

- 扩展最小 `EmbodiedPoseState` 为只读 `BodyStateSnapshot`，先镜像而非替换现有行为。
- 为认证、表情、旧动作、空闲、行走、物理、鼠标注视、拖拽和恢复建立写入者/资源/恢复清册。
- 增加本地 `EmbodiedEvent` 记录与 EditMode 状态机测试。

**AC-ULC-A**：测试能证明任意已登记写入者的所有者和资源；认证取消、超时和退出均留下终态并无锁残留；视觉行为未因镜像层变化而改变。

### Phase B — 单一仲裁与安全恢复（P0）

- 将各写入路径逐类迁为协调器管理的执行器/适配器；未迁移项必须在状态中显式标记，不能伪称已统一。
- 实现优先级、冲突、取消、恢复和渲染失效的统一处理。

**AC-ULC-B**：生产路径不存在未登记的持续参数写入；冲突、拖拽、停止、退出与渲染重建测试均能恢复并解释。

### Phase C — 事件、注意力与具身经验（P1）

- 接入直接交互事件和用户授权模式事件，建立有界事件时间线。
- 将动作结果存为最小具身经验，供记忆、情绪和策略读取。

**AC-ULC-C**：系统能解释一次动作的发起、结果、恢复与冷却/替代原因；事件过期、测试隔离和隐私断言通过。

### Phase D — 受限主动行为（P1）

- 本地规则先产生低打扰语义意图；LLM 只能提案，不拥有执行权。
- 情绪和人格只能调整已认证轻动作、语气和注意力时长。

**AC-ULC-D**：主动行为不打断输入/拖拽/掉落，断网零云端使用，用户可看到和关闭其原因与频率。

## 5. 实施授权边界

- **允许修改**：`Assets/Scripts/Embodied/`、`Live2DRenderer.cs`、既有动作/表情/桌面交互调用方、对应 EditMode 测试、隔离测试脚本、任务包和直接真相文档。
- **禁止修改**：全局决策、模型参数映射和模型资产、工具权限、桥接鉴权、云端成本策略；涉及这些范围或新增数据收集时必须记录 `BlockedByDecision` 并交由人工决定。
- **任务边界**：每个任务包只能在自身 `allowedPaths` 内实施；本指导文档不授权用“迁移”名义改变未经认证的动作视觉效果或将候选动作开放给 LLM。

## 6. 允许范围、禁止范围与证据

允许修改：`Assets/Scripts/Embodied/`、`Live2DRenderer.cs`、现有动作/表情/桌面交互调用方、相应 EditMode 测试、隔离测试脚本和直接文档。

禁止修改：全局决策、模型参数映射、模型资源、工具权限、桥接鉴权、云端成本策略；涉及这些内容或新增数据收集时必须 `BlockedByDecision`。

每个阶段至少运行 `build.ps1 -Quick`、`build.ps1 -RunTests`、文档索引生成；涉及真实渲染/输入/退出时再运行隔离 Player 验收。只有测试与可复核运行日志齐全时，才可在 `docs/truth/` 记录完成事实。
