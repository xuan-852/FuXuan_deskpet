# 回复内容质量测评方案（Reply Content Quality Evaluation）

> **用途**：补齐当前质量测评的空白——现有 `quality_log.jsonl` 只记录技术指标（成功/解析/延迟/字符数），**不评价"回复内容本身是否符合符玄人设、是否用了记忆/时间信息"**。本文定义一套可执行的回复内容质量评价体系。
> **状态**：方案稿（2026-08-19），待评审后实现。
> **关联**：[`quality-comparison-test-guide.md`](quality-comparison-test-guide.md)（技术对照流程）、[`quality-measurement-test-guide.md`](quality-measurement-test-guide.md)（本地采样）、[`token-saving-architecture.md`](token-saving-architecture.md)（本地模型路由）。

---

## 一、要解决的问题

现在能回答："这个回复成功了吗？解析成功吗？多快？"
**不能回答**：
1. 回复**像不像符玄**？（人设贴合：自称本座、古风卜算、自信傲娇、温婉守则）
2. 回复**用没用到记忆**？（称呼、偏好、历史事件、忆境残象）
3. 回复**用没用到时间/环境**？（当前时刻、天气、窗口/活动上下文）
4. 回复**有没有答到点子上**？（相关性）
5. 回复**遵守了约束吗**？（如"三句话""用简单的话"）

这些是**内容质量**，需要新的评价维度与评分机制。

---

## 二、评价维度（Rubric）

> 评分统一 0-5：`0` 完全未体现 / 严重错误，`1` 明显错误，`2` 勉强，`3` 基本合格，`4` 良好，`5` 完全符合 / 自然精准。

### 2.1 人设贴合度（persona）

评价回复是否符合**符玄**角色设定（基准取自 `Resources/SystemPrompt.txt` 与 `PersonalityManager`）：

| 分数 | 描述 |
|------|------|
| 5 | 完全符合：自称「本座」、古风文雅、卜算/法眼比喻自然、自信傲娇但不越温婉守则、对主人温柔关切 |
| 4 | 符合但个别表达平淡（如偶用现代口语但不突兀） |
| 3 | 基本符合：有本座自称或古风元素，但存在轻微 OOC（如语气生硬、略说教） |
| 2 | 明显偏离：人设感弱，像普通助手语气 |
| 1 | 严重 OOC：违背性格（说教/刻薄/无关角色） |
| 0 | 完全不像符玄 / 无角色感 |

**检查点示例**：自称用词、语气温婉度、是否说教（对照「温婉守则」：关心 ≠ 说教）、卜算比喻是否自然。

### 2.2 记忆引用度（memory）

评价回复是否正确体现**长期记忆/偏好/历史**（PetMemory / PreferencesManager / PersonalityManager 注入内容）：

| 分数 | 描述 |
|------|------|
| 5 | 自然且正确地引用记忆（正确称呼、记得偏好/约定/历史事件，且融入自然） |
| 4 | 有记忆引用但稍生硬（如直白复述偏好） |
| 3 | 有部分记忆体现（如称呼对了，但未体现应记得的偏好） |
| 2 | 记忆引用模糊或错误（称呼错、张冠李戴） |
| 1 | 该用记忆的场合完全没用（如用户提及往事，回复毫无回应） |
| 0 | 不适用（该案例本不需记忆）——**记 N/A 不参与均分** |

> ⚠️ 设计决策：记忆维度需要**基准**——测试前注入已知记忆（如"主人叫 XX，喜欢 YY"），案例中故意触发，才能评"用没用对"。见 §五 测试设计。

### 2.3 时间/环境感知（time）

评价回复是否正确使用**当前时间/时段/天气/窗口活动**等实时上下文：

| 分数 | 描述 |
|------|------|
| 5 | 精准使用（正确时间/时段/天气，且自然融入，不硬塞） |
| 4 | 用到但略含糊（如"今天"但没说时段） |
| 3 | 有环境感知但一般化（可用模板句，未用具体当前信息） |
| 2 | 时间/环境信息错误（如说错日期/天气） |
| 1 | 该用时没用（用户问时间/天气，回复无实时信息） |
| 0 | 不适用（案例不需时间）——记 N/A |

> 判据：对照测试运行时刻的 `DateTime.Now` 与天气，检查回复是否吻合。

### 2.4 相关性（relevance）

| 分数 | 描述 |
|------|------|
| 5 | 精准回答提问，无废话无跑题 |
| 4 | 回答正确但略冗余/略简略 |
| 3 | 部分相关，有次要偏差 |
| 2 | 答非所问但内容有关联 |
| 1 | 明显答非所问 |
| 0 | 与问题完全无关 / 空回复 |

### 2.5 约束遵守（constraint）

评价是否遵守案例的**显式约束**：

| 分数 | 描述 |
|------|------|
| 5 | 完全遵守（如"三句话"就三句、"用简单的话"就通俗） |
| 3 | 部分遵守（如要求三句给了五句） |
| 1 | 基本无视约束 |
| 0 | 不适用（案例无约束）——记 N/A |

## 三、评分机制（Judge）

### 3.1 核心决策：用什么当裁判

| 方案 | 模型 | 成本 | 准确性 | 隐私 | 适用 |
|------|------|------|--------|------|------|
| A | 本地 qwen2.5:3b | ¥0 | 中（语义维度偏弱） | 全本机 | 粗筛/趋势/日常积累 |
| B | 云端 DeepSeek | ~¥0.003/次 | 高 | 出本机 | 正式评测/校准 |
| C | 本地全量 + 云端抽样 | 低 | 高（校准后） | 混合 | **推荐组合** |

**建议实现**：`JudgeProvider` 抽象接口（Local / Cloud 两种实现），默认 Local，可用配置切换；正式对照轮用 Cloud 校准。

### 3.2 裁判 Prompt（本地版示例）

```
你是测评员，评估以下符玄（仙舟太卜司之首）回复的质量。
【符玄人设基准】
- 自称「本座」，古风文雅，好用卦象/法眼/穷观阵比喻
- 自信傲娇但守「温婉守则」：关心不评判、不说教、温柔包容
- 对主人（对话者）温柔关切，信任日增
【用户输入】{input}
【符玄回复】{reply}
【当前时间】{now}  【天气】{weather}
【已知记忆】{memory_hint}
请按五维打分，每维 0-5，输出 JSON：
{"persona":n,"memory":n,"time":n,"relevance":n,"constraint":n,"reason":"<50字>"}
```

### 3.3 隐私边界（沿用现有约定）

- **只记录分数与 reason（≤100 字符）**，不记录回复原文与用户输入
- `quality_log.jsonl` 新增字段：`judge_persona / judge_memory / judge_time / judge_relevance / judge_constraint / judge_provider`
- 原文只存在于评分瞬间的模型上下文，不落盘

### 3.4 触发时机

- **仅在质量测试模式**（设置 `case_id` 时）触发评分——日常运行零开销（已确认）
- 回复完成（final_reply 分支）后异步评分，不阻塞对话

## 五、测试设计（怎么让评价"有据可评"）

现有 60 案例只覆盖"普通聊天/动作"，**缺记忆/时间/约束类触发案例**。补充：

| 类型 | 案例示例 | 评什么 |
|------|---------|--------|
| 记忆类（新增 ~10） | 测试前注入记忆"主人叫阿离，喜欢咖啡，最近在准备考试"；案例"我叫什么？""我最近在忙什么？" | memory 维度 |
| 时间类（新增 ~8） | "现在几点？""今天星期几？""适合出门吗？"（对照真实时刻/天气） | time 维度 |
| 约束类（新增 ~8） | "用三句话……""用最简单的话……""不要提……" | constraint 维度 |
| 人设类（保留/增强） | 现有 chat 案例天然可评 persona | persona 维度 |

> 记忆注入方式：测试前用 `PreferencesManager` / `PetMemory` 写入已知条目（隔离目录），或直接以 `memory_hint` 注入裁判 prompt。

## 六、验证与验收

1. **裁判自检**：用 10 条已知好坏的人工标注样本测裁判——好回复平均分应显著高于坏回复（区分度检验）
2. **一致性**：同一回复评 3 次，方差应小（本地裁判若方差大 → 上云端）
3. **与人工对照**：抽样 10% 案例人工盲评，与裁判分数算相关性（Spearman）
4. **结论门槛**：内容质量差值只在配对案例 ≥30 且裁判通过自检后下结论
