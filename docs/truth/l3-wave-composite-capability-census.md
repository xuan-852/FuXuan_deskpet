# L3 招手组合能力普查（2026-09-18）

## 结论

当前符玄模型已经证明具备制作“完整招手候选”的最低底层通道：可见的抬臂、手腕候选、手型切换，以及可复位的面部候选通道。它**不等于招手动作已完成或已认证**；目前没有任何招手曲线、正式映射、生产数据或 LLM 可调用技能。

最重要的限制是：单独扫动手腕或普通手指时，正面可见差异很弱。真正可读的招手必须在抬臂姿态中，利用手型切换形成面向观者的手掌，并对手腕作有限、节律化的往返；脸部还须在组合动作内再次人工验收。

## 隔离运行时六预设循环验证（未认证）

新增仅测试模式可用的 `@@sim:gesture:wave-matrix:cycle` 入口，按固定顺序循环播放 `normal`、`sword`、`arm94`、`arm97`、`arm118`、`body-head`。已使用临时构建、隔离 `FU_XUAN_DATA` 和 `.test_mode` 验证完整一轮：六组均输出 `cycle-preset` 与 `preset-completed`，随后发送 `@@sim:gesture:wave-matrix:cancel` 能完成统一清理；再发送 `@@test:quit` 输出 `[EmbodiedSafeRecovery] recovered: test-exit` 与测试退出清理日志。

循环期间只持有一个 `CandidateTest` 输入租约；旧实现曾在预设之间把矩阵参数清零，导致可见窗口中的手部图层消失，该运行记录现降级为无效测试入口证据。当前修复改为首次写入捕获运行时 baseline，预设切换、取消和结束时恢复实际 baseline、释放租约并解除移动锁。该证据只证明测试循环、互斥写入和安全恢复链路可运行，不证明任何预设的视觉语义，也不证明六组组合成自然招手。

矩阵入口现只写当前 preset 的目标参数，不再统一清零普通手指组、剑指手指组、手型切换、手臂、躯干或头部候选。修复后的循环仍需真实可见窗口人工确认；`normal`/`sword` 的手型、`arm94`/`arm97`/`arm118` 的肢体作用以及 `body-head` 的方向均未认证。

## 风险与下一步

`Param102` 在静态映射文件中标为 `0..1`，但组合探针从运行时模型范围取得的目标为 `15`（以 0.5 比例缩放）。这说明静态名称和范围只能是候选资料，后续制作前必须以运行时原生范围为准，并在更保守范围内重新取样。

下一步仍应先在真实可见窗口中人工确认 `normal` 是否为单一正常掌心、`sword` 是否为单一剑指，以及 `body-head` 是否为目标方向的同步侧倾；之后才可设计包含腕部往返和表情的完整动态序列。候选必须确认“手在挥、看起来友好、结束自然”后，才可讨论认证与受控暴露。
