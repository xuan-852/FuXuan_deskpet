## 1. 目标与非目标

### 1.1 首个可运行里程碑

本计划指导创建一个**高还原二创符玄 Live2D 模型**，首个交付目标是“私有研发可运行”：

- 缩略图、静态正面和基础动态下都能立即识别为符玄；
- 发型、发饰、服装、袖口、裙摆、鞋和关键装饰完整，不以裸立绘或临时占位服装作为首版交付；
- 支持呼吸、眨眼、眼球轻跟随、头部轻微变化、身体微动、自然回中；
- 支持头发、发饰、衣袖、裙摆和挂件的基础低幅物理；
- 能在 Unity 隔离场景中加载、显示、交互、停止和恢复；
- 为后续肩臂、手、复杂表情、走路、手势和特效保留可编辑的层、参数和资源插槽。

“高还原”指角色识别点、服饰结构和整体气质接近符玄；不要求逐像素复制任何已有模型，也不要求复刻当前模型的全部参数或动作。

### 1.2 非目标

首个里程碑不承诺：

- 完整战斗动作、复杂手势、完整走路动作或自主行为；
- 直接继承当前模型的参数 ID、曲线、物理配置、网格或贴图；
- 将未经过 Probe 和动作认证的参数或动作开放给 LLM；
- 公开发布、商业使用、再分发或向第三方提供模型工程；
- 仅凭“可下载”“开源”“用于视频”等描述推断外部素材拥有改作或发布许可。

## 3. 资产、参考与权利边界

### 3.1 必须分别登记的权利对象

以下对象不能因为放在同一个项目目录中就视为拥有相同许可：

1. 符玄角色及相关视觉识别元素的著作权、商标或平台规则；
2. 新绘制的立绘、纹理、网格和 Cubism 工程；
3. 现有符玄模型包、其作者的绘稿和绑定数据；
4. 其他开源、免费或“受伤”模型及其配套素材；
5. Cubism 编辑器、Cubism SDK、运行时和导出工具；
6. 本项目代码、脚本、测试证据和生成配置。

每一项都要在 `license-register.md` 中记录来源 URL 或文件来源、访问日期、原始许可文本、允许用途、是否允许改作、是否允许私用、是否允许再分发及当前结论。

### 3.2 允许参考的范围

用户已确认允许借用已有像素布局来提高 AI 创作速度。这里的“布局参考”限于可抽象描述的设计信息，例如：

- 画布比例、部件占位框和相对尺寸；
- 头发、发饰、袖子、裙摆等部件的分层思路；
- 锚点、遮挡关系、绘制顺序和纹理密度；
- 参数命名的组织方式和工作流经验。

AI 可以把这些信息转写为新的部件规格、线框、命名表和布局草图，然后重新绘制或使用明确允许改作的素材。

### 3.3 不得默认复制的内容

以下内容不能因为本项目首期仅供私有研发就自动复制：

- 原始像素、纹理、立绘局部、笔触或可识别的逐层抠图；
- 原模型的网格、贴图、`.moc3`、Cubism 工程或导出物；
- 参数曲线、物理配置、动作关键帧和材质配置；
- 任何受限素材的批量转换、去水印、拆层或重新打包。

若某项素材许可明确允许改作，应保存许可证据并标注实际使用范围。许可不明确时只能做布局和行为的抽象参考，素材进入新模型源文件前必须停止并标记 `BlockedByEvidence`。

**私有研发可运行不等于公开发布、商业使用或再分发许可。** 未来若要展示、发布、出售、随安装包分发或提供源工程，必须重新进行权利复核并取得必要授权。

## 4. 给建模 AI 的执行协议

以下提示词可作为交给建模 AI 或人工执行代理的总指令：

> 你正在创建一个高还原二创符玄 Live2D 模型。先读取本计划、`source-register.md`、`license-register.md` 和 `model-spec.yaml`，再开始绘制或绑定。你可以参考已登记素材的像素布局、比例、锚点、遮挡关系和分层经验，但不得在没有明确许可的情况下复制像素、纹理、网格、贴图、Cubism 工程、参数曲线、物理配置或导出文件。每个外部素材都必须可追溯；许可不确定时停止使用并输出 `BlockedByEvidence`，不要用“开源”“免费”或“私用”自行推断权限。每个阶段都要保存源文件、生成物、哈希、变更记录和验收证据。不得覆盖现有生产模型，不得把未验证参数写入正式映射，不得把原始参数 ID交给 LLM，不得把临时测试数据写入生产数据目录，也不得把候选动作描述为已认证能力。阶段完成后只提交本阶段产物和门槛结论。

每个阶段必须回答：

1. 使用了哪些输入，来源和许可是什么；
2. 修改或生成了哪些文件，哪些是源文件、哪些是生成物；
3. 采用了哪些部件、参数、物理或遮挡设计；
4. 产生了什么可复核证据；
5. 哪些条件未满足，是否应回退或标记阻断；
6. 下一阶段允许读取什么，不允许越过什么边界。

## 5. 分阶段生产流程

### Stage 0：项目与许可冻结

**目的**：在绘制前固定范围、版本和素材权利，不让后续 AI 用不确定来源填空。

**输入**：本计划、产品方向基线、现有模型的观察性参考、Cubism 工具版本信息。

**执行**：

- 建立新模型专用工作目录，不与现有 `Assets/Live2D/Models/Fuxuan/` 混放；
- 为每个参考文件、链接、截图或外部模型建立来源记录；
- 固定首版目标、画布比例、显示姿态、服饰清单和基础动态清单；
- 为模型建立版本号、变更日志和资源哈希策略。

**产物**：`source-register.md`、`license-register.md`、`model-spec.yaml`（或等价结构化规格）、`CHANGELOG.md`。

**门槛**：用途、改作、私用、分发和商业状态逐项有结论；不明确素材只能进入隔离参考区。未满足时标记 `BlockedByEvidence`。

### Stage 1：视觉规格与画布布局

**目的**：先固定“像不像符玄”和“衣服是否完整”，再进入复杂绑定。

**执行**：

- 固定脸型、发型、发饰、眼眉口、服装主色与层次、袖口、裙摆、鞋和关键识别点；
- 参考已有布局时只记录部件框、比例、锚点、遮挡关系和纹理密度，不复制受限像素；
- 设计正面中性姿势，保证呼吸、转头、闭眼、张嘴和衣摆运动时不会露出未绘制区域；
- 编写部件清单、绘制顺序表、表情目标表和服饰物理意图表。

**产物**：正面中性姿势图、布局线框、部件分层图、遮挡/绘制顺序表、表情目标表、服饰物理意图表。

**门槛**：缩略图和灰度轮廓仍可识别为符玄；服饰结构完整；每个参考元素都有来源和使用结论；没有未授权像素混入。

### Stage 2：分层绘稿与可变形资源

**目的**：为 Cubism 变形和后续动作准备足够、干净、可追溯的绘制层。

**建议分层**：

- 头部、脸、眼白/瞳孔、眉毛、嘴和脸部阴影；
- 前发、中发、后发、发饰、挂件；
- 颈部、肩部、上衣、领口、袖子、手臂和手；
- 腰部、裙摆前后层、腿部、鞋和下摆装饰；
- 阴影、高光、独立特效和不参与身体语义的装饰。

**执行**：

- 会运动的边界保留足够冗余，补齐转头、闭眼、张嘴、抬臂和裙摆暴露区域；
- 用稳定命名规则标识部件、左右侧、前后层、遮罩和物理候选；
- 输出透明检查图、缺口清单、尺寸/压缩记录和源文件版本。

**门槛**：每个首版动态都能找到独立层或合理组合；无大面积穿帮、透明边污染和错误遮挡；纹理来源可追溯。

### Stage 3：Cubism 建模与参数设计

**目的**：建立新模型自己的可编辑参数空间，不把旧模型命名当作事实。

**执行顺序**：

1. 先建立中性姿势和基础网格，再做局部变形；
2. 设计头部 X/Y/Z、身体 X/Y/Z、呼吸、眼睛开合/眼球、眉、嘴、头发和服饰物理输入；
3. 为后续肩臂、手、复杂表情和特效预留独立通道，但不因预留就宣称已可用；
4. 为每个参数记录新模型专属 ID、native minimum/default/maximum、默认值、影响层、写入者和资源归属；
5. 把模型参数事实与语义名分开保存，后续由 Probe 证据生成候选映射。

**产物**：可编辑 Cubism 工程、参数字典、部件影响表、变形器/网格说明、默认姿态快照。

**门槛**：中性姿势可复位；单参数可写回且不会损坏其他部件；参数资源归属明确；没有同一帧多写入者的设计性冲突。

### Stage 4：物理、表情与基础生命动态

**目的**：优先获得稳定、低幅、可恢复的生命感和服饰表现。

**基础动态清单**：

- 呼吸：胸腹或身体整体的低幅周期变化；
- 眨眼：左右眼可独立闭合并稳定复位；
- 注视：眼球轻跟随，带限幅和回中；
- 头部微动：头部 X/Y/Z 的低幅、非机械周期变化；
- 身体微动：轻微重心或姿态变化，不抢占高优先级动作；
- 回中：停止、取消和异常后逐步回到安全姿态。

**服饰物理优先项**：刘海/发尾、发饰、袖口、裙摆和挂件。先使用保守的输入幅度、阻尼、速度和稳定帧，避免夸张摆动掩盖绘制缺陷。

**门槛**：连续小幅变化不跳变；停止后在有限时间内稳定；无明显穿模、断层、抖动、物理爆炸或裙摆穿过身体；物理附属物不被 LLM 逐帧直接控制。

### Stage 5：导出与清单

**目的**：获得可重建、可核对、不会覆盖旧模型的导出包。

**执行**：

- 导出 `.moc3`、`.model3.json`、`.physics3.json`、`.cdi3.json`、纹理和可编辑源工程；
- 生成 manifest，记录工具版本、模型版本、资源哈希、相对路径、参数清单和许可标记；
- 通过 Cubism Viewer 或等价本地工具打开并检查引用；
- 将导出物放入独立候选目录，不直接覆盖现有 `Assets/Live2D/Models/Fuxuan/`。

**门槛**：导出物可打开；所有引用相对路径正确；源工程可重新导出；导出包与 manifest 哈希一致。

### Stage 6：Unity 隔离导入

**目的**：先证明新模型能在项目渲染链路中工作，再考虑生产接入。

**执行**：

- 在独立候选目录导入 Prefab 和模型资源；
- 只验证加载、透明、尺寸、材质、绘制顺序、基础输入和停止恢复；
- 使用独立 `FU_XUAN_DATA`，并在其中创建 `.test_mode`；
- 必要时使用独立测试场景或 Probe Window；
- 不修改正式 `fuxuan_map.json`、生产动作、LLM 接口或现有模型资源。

**门槛**：新模型与生产模型可并存；Unity 无缺失引用和明显渲染错误；隔离测试不污染生产记忆、配置和动作记录。

### Stage 7：Probe 能力普查

**目的**：用新模型自己的运行时事实建立候选能力清册。

**执行**：

- 运行全量参数发现；
- 对候选参数执行基线/min/mid/max/reset 三轮采样；
- 对关键参数执行连续 sweep，检查插值而非只看端点跳变；
- 对身体和服饰物理使用独立 physics writer 模式；
- 对头、躯干、眼脸、服饰物理、左右手臂候选和服饰跟随执行组合探测；
- 记录模型/资源哈希、PNG、JSON、复位差、重复性和时序指标；
- 将结果标为候选、`Supporting` 或 `Conditional`，不自动写正式映射。

**门槛**：机械写入/读回、视觉可见、复位、重复性和时序证据齐全；归因不确定、形变危险或复位失败的能力保持未认证。

### Stage 8：语义映射与基础运行时适配

**目的**：只把已经有充分证据的首版生命动态接入运行时。

**执行**：

- 根据 Probe 证据创建新模型专属映射和语义适配；
- 不把旧模型参数 ID、曲线、物理数值或动作模板直接移植为新模型事实；
- 首轮只接入基础生命动态、服饰表现和必要的停止/恢复；复杂手势、走路和特效留在候选层；
- 所有运行时写入继续经过参数提交边界、动作协调器和租约/资源规则；
- LLM 只看到已认证的技能名、前置条件和降级策略，不看到原始参数 ID 或数值。

**门槛**：模型切换、动作停止、取消、恢复、异常退出和渲染重建不遗留锁、姿势或参数污染；未经认证的参数不进入常规动作接口。

### Stage 9：首版验收与后续扩展

**目的**：把“能运行”与“能安全作为身体能力使用”分开。

先验收“私有可运行的基础生命动态 + 完整服饰”，再单独认证手势、上半身动作、走路、复杂特效和自主行为。每个后续技能必须绑定：模型版本、证据哈希、前置姿态、资源占用、进入/执行/收束/取消、成功指标和降级方案。

只有达到 `Certified` 的技能才能进入常规 LLM 身体接口；`Supporting`、`Conditional`、`Unreliable`、`EffectOnly` 和 `Unsupported` 只能按各自规则由内部系统使用或拒绝。

## 7. 验收矩阵

| 验收 ID | 条件 | 证据 | 通过标准 |

## 8. 失败、阻断与恢复

- **许可不明确**：标记 `BlockedByEvidence`，将素材留在隔离参考区，不进入新模型工程；补齐来源或替换素材后重试。
- **识别度不足或服饰缺失**：退回 Stage 1/2，不进入绑定和能力认证。
- **大面积穿帮、物理不稳定或复位失败**：退回 Stage 2/3/4，优先修复分层、网格、输入幅度和阻尼。
- **导出或 Unity 引用错误**：保留上一版本候选目录，修复新版本后重新导出，不覆盖旧模型。
- **Probe 证据不足或语义归因不确定**：不更新正式映射、不开放动作、不向 LLM 暴露。
- **运行时出现锁、姿态或参数残留**：停止生产接入，先复核协调器、提交桥接、停止收束和测试隔离。
- **产品方向、公开发布、商业授权或资源复用发生争议**：标记 `BlockedByDecision`，记录冲突来源、影响和待决选项，暂停越过争议点的实施。
